# 2026-08-28

Fleet review pass over this repo (checklist A-G from the plugin-collection review), followed by
the declarative settings port. Two commits, plus a follow-up for the review findings.

## Decisions taken

**The archive is the artifact that matters.** The Obsidian community catalog reviewer builds and
lints the _git archive_, not the working tree. Anything `.gitattributes` strips is invisible
locally and load-bearing there. `eslint.config.ts` was still `export-ignore`d, so the reviewer had
been falling back to its own ruleset all along. Verified the fix with a real archive
(`git archive --format=tar HEAD | tar -x -C /tmp/x && bun install && bun run build && bun run lint`),
not by reading the file.

**`brands` replaces the default list, it does not extend it.** `obsidianmd/ui/sentence-case` reads
`options?.brands ?? DEFAULT_BRANDS`, so naming our own brands silently dropped the plugin's 46
built-ins — `Obsidian`, `Git`, `Markdown`, `GitHub`, `Windows`. The reviewer runs the plugin's own
ruleset and keeps enforcing every one of them, so the effect was hiding findings from ourselves,
not removing them. Spreading `DEFAULT_BRANDS` surfaced eight genuine ones. Also learned the hard
way: never add an ordinary UI word such as `Settings` as a brand, because brand casing is enforced
_both_ ways and every lowercase "settings" then becomes a violation.

**Sentence case over a local disable.** The `obsidianmd/ui/sentence-case` disable carried a "false
positives" comment. It was not false positives: UI text really did say "git", "markdown" and "file
recovery" where the brand casing is `Git`, `Markdown` and `File Recovery`. Fixed the text.

**`updateSettings`, not `saveSettings`, is the runtime write path.** The old tab mutated
`plugin.settings` and then persisted, so a failed write left memory ahead of disk and the control
showing a value that was never stored. Now: persist first, commit to memory only on success, and
serialize the writes so each mutation derives from the previous _committed_ state.

This plugin has **two** settings writers — the pane, and `setComparisonMode` driven by the in-panel
comparison toggle, which is one click away from a pane edit. Both route through `updateSettings`.
Before, they could interleave and the second commit would drop the first edit.

## Shipped

Commit 1 — catalog alignment:

- `.gitattributes`: stop `export-ignore`ing `eslint.config.ts`.
- Re-enabled `obsidianmd/ui/sentence-case` (spreading `DEFAULT_BRANDS`) and raised
  `no-explicit-any` from `warn` to `error`; fixed the resulting UI text.
- Pinned `@types/bun` and declared `@types/node` directly, named both in tsconfig `types`.
- Added the collection's `overrides` block: 33 advisories (1 critical) to 0, with no `audit fix`.
- `bun@1.4.0`; `bun test --isolate` everywhere (CI and release ran bare `bun test`, which silently
  drops the flag); CI now gates on `bun audit --audit-level=high`.

Commit 2 — declarative settings:

- Six settings ported to `getSettingDefinitions()`; `minAppVersion` 1.8.7 to 1.13.0, `obsidian`
  typings 1.12.0 to 1.13.1 (`Plugin.settings?: unknown` now exists, so the field needs `override`).
- Serialized persist-then-commit `updateSettings`; `setComparisonMode` routed through it.
- Side effects (`syncPastViewRibbon`, `refreshAllViews`) preserved and now run only after the write
  lands.
- The async Git-availability probe re-checks `settingEl.isConnected` before writing: the pane can
  close or re-render while it runs.
- Ported the collection's `settings-guard.spec.ts`; documented the traps in `AGENTS.md`.

Commit 3 — review findings (codex, gpt-5.6-sol, xhigh; 5 findings, 0 on the port's trap classes):

- The support block renders inside a `.setting-item`, which is a flex **row** — heading, buttons
  and badge would have been laid out side by side. Added `.tm-settings-stack` to put the row back
  into block flow.
- "Follow me on X" had become a whole-row `action:` with no button. Restored the CTA button via a
  `render:` hook — the old tab had a real button and the docs describe one.
- Added `settings-write.spec.ts`: 11 behavioral tests for the queue, the rollback, the validation
  and the side-effect ordering. Each was checked against a deliberately regressed `updateSettings`
  to confirm it actually fails — the first version of the ordering test passed even with the commit
  order reversed, because the write chain defers to a microtask.
- Documented the 1.13.0 requirement in `README.md` and `docs/configuration.md`, and synced the docs
  with the renamed UI strings.

## Upstreamed to the template

- The `DEFAULT_BRANDS` fix. Every repo in the collection that copied the `brands` block has the
  same blind spot.
- This repo's `__TM_CHANGELOG__` build define, generalized to `__PLUGIN_CHANGELOG__`. The template
  still used `import changelog from '../../CHANGELOG.md' with { type: 'text' }`, and markdown
  import attributes are not resolvable on the older Bun the reviewer builds with.
