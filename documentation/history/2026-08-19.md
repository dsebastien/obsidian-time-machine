# 2026-08-19

## Fix: cursor-following switched to the wrong note in split panes (issue #7, regression report on 1.3.0)

- Root cause: `syncToCursorFile()` resolved the target file via `resolveActiveFile()`, whose `getActiveFile()` fallback returns the _most recently opened_ file. Notes rendered inside a continuous-scroll pane (Daily Notes Editor) are never opened in a leaf, so in a split the fallback resolved the other pane's note whenever a sync fired while `workspace.activeEditor` was momentarily null (focus moving into the sidebar, `active-leaf-change` during a slider mousedown). The 1.0.6 focus-inside-own-view guard only narrowed the window; it never removed the wrong resolution.
- Fix: cursor-following now trusts ONLY `activeEditor.file` and does nothing when it is unset. Regular tab switches remain covered by `file-open`. The `getActiveFile()` fallback survives only in `resolveActiveFile()`, used for the initial file when the view first opens. Business rule added.
- Regression test: sync with `activeEditor = null` and `getActiveFile()` pointing at another note must not call `updateForFile`.

## Feature: version-to-version diff comparison mode (issue #8)

Implemented per `documentation/plans/diff-comparison-mode.md` (plan removed after completion):

- New setting `diffComparisonMode: 'current' | 'next'` (default `current`), persisted from an in-panel toggle — no settings-tab UI.
- `computeAndRenderDiff` branches on the mode: `next` diffs `snapshots[i].data → snapshots[i-1].data` (filtered array, newest-first); at `i === 0` both modes diff against the current file content.
- Diff toolbar gained a "Compare with: Current file / Next version" segmented toggle; it stays visible even when the active mode shows "No differences found". Toolbar layout switched from `justify-end` to `justify-between`.
- Per-hunk restore is hidden in `next` mode (hunks relate two historical versions) and `handleRestoreHunk` refuses to run in that mode as a second guard. "Restore entire version" works in both modes.
- Fixed a latent init quirk while wiring this: the slider auto-select fires before `this.diffViewer` is assigned, so the initial diff never rendered until first interaction. `renderContent` now renders the initial diff explicitly after constructing the viewer.
- Tests: view spec covers mode pairing, `i === 0` equivalence, persistence + recompute, and the hunk-restore refusal; new `diff-viewer.spec.ts` covers toggle rendering, hidden hunk restore, and mode-change callbacks (recording mock DOM).
- Docs: usage guide "Comparison modes" section, README feature bullets, Business Rules (Compare Mode rewritten, Restore Safety invariant added).
