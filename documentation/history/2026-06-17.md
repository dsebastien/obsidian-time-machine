# 2026-06-17

## Done

- Fixed GitHub issue #7 ("Doesn't work well with Daily Notes Editor", reported by hmijail). Moving the text cursor between notes in a continuous-scroll view now switches Time Machine to the note the cursor is in.

## Root cause

The view only tracked files via the workspace `file-open` event. The [Daily Notes Editor](https://github.com/Quorafind/Obsidian-Daily-Notes-Editor) plugin renders many daily notes inside a **single leaf** (continuous scroll), so `file-open` does not fire when the caret moves from one embedded note to another. The view kept showing whatever file last triggered `file-open` (often a different tab/file). Editing worked only because a `modify` event happened to land on the right path.

Key API insight: `workspace.getActiveFile()` returns the leaf's representative file, but `workspace.activeEditor.file` resolves the **focused embedded editor** — i.e. the note actually holding the caret.

## Fix

`plugin.ts`:

- New `resolveActiveFile()` — prefers `workspace.activeEditor?.file`, falls back to `getActiveFile()`.
- New `syncToCursorFile()` — resolves the cursor's file and calls `updateForFile` on open views only when the path changed. Guarded to no-op when no file resolves, so caret moves into the sidebar / the view itself never clear the displayed history.
- Wired to a debounced (`150ms`, trailing) `selectionchange` DOM handler on `activeDocument`, plus the `active-leaf-change` workspace event. The trailing debounce means continuous typing/arrowing only triggers one sync once the caret settles.

`time-machine-view.ts`: `onOpen` now seeds from `plugin.resolveActiveFile()` instead of `getActiveFile()` for consistency.

`eslint.config.ts`: added `activeDocument` / `activeWindow` to globals (obsidian popout-aware globals) to satisfy `no-undef`.
