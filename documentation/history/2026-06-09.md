# 2026-06-09

## Done

- Fixed GitHub issue #6 ("Wrong diffs", reported by hmijail on Time Machine 1.0.3): the diff panel rendered nonsensical additions/deletions for small edits. Root cause + fix below.

## Root cause

The diff was purely **line-based** (`structuredPatch` from the `diff` library, `diff.service.ts`). Obsidian notes are prose — a paragraph is one long soft-wrapped line — so changing a couple of words reported the entire paragraph as one removed line plus one added line. The text was all present (reporter: "the text is right") but the red/green blocks were near-identical whole paragraphs, so the +/- "don't make sense". Obsidian's File Recovery plugin avoids this with word-level diffing, which the reporter pointed to as the desired behavior.

Two secondary bugs found and fixed:

- `\ No newline at end of file` — when a version has no trailing newline, `structuredPatch` emits this marker line; the renderer showed it as a stray `\`-prefixed context line.
- CRLF/LF mismatch — no line-ending normalization anywhere, so a snapshot stored with `\r\n` vs a current file with `\n` reported every line as removed+added.

## Fix

Kept the line-based hunk structure (so per-hunk restore stays line-addressable, per Business Rules) and added **inline word-level highlighting** within changed lines:

- `diff.service.ts`: normalize CRLF→LF before diffing; new `buildRenderLines()` strips the no-newline marker, pairs consecutive removed/added lines, and runs `diffWordsWithSpace` (already in the bundled `diff` v8.0.3) per pair to tag only changed words. Result attached to each hunk as `renderLines: DiffLine[]`.
- `diff.intf.ts`: new `DiffLine` / `DiffSegment` (`same|added|removed`) types; `DiffHunk` gains `renderLines`. Raw `lines` kept untouched for `restore.service.ts`.
- `diff-viewer.ts`: renders `hunk.renderLines`, emitting per-segment spans (`tm-diff-word-added` / `tm-diff-word-removed`) inside the existing two-line -/+ layout.
- `styles.src.css`: `.tm-diff-word-added` / `.tm-diff-word-removed` (stronger green/red tints).

Two-line layout with inline word highlights was the chosen style (over a single merged File-Recovery-style line) — smallest change, preserves the existing per-hunk restore buttons.
