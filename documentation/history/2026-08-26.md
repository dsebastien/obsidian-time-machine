# 2026-08-26

## Planning: past view (issue #9)

No code changes. Issue #9 was a brainstorm bundling four features; it was scoped down and split.

**#9 now tracks only**: in-editor past view + side-by-side compare. Split out:

- #10 — export a note's version history to markdown (the original request from Daniel Prindii)
- #11 — live ` ```time-machine ` embed block rendered by a markdown post-processor
- #12 — freeze version history into a note as static markdown

**Plan**: `documentation/plans/past-view.md`.

Key decision: "past view" and "side-by-side" are the **same view**. One read-only `ItemView`
opened via `createLeafBySplit(leaf, 'vertical', true)` to the left of the live editor — the
right pane stays the user's real, editable note and Obsidian supplies the splitter. Opened as
a tab instead of a split on mobile/narrow workspaces, which is the full-width "past view".

Other locked decisions (see the plan's decisions table for rationale):

- Left body renders the old version via `MarkdownRenderer.render`; the diff switch replaces
  the body with the existing `DiffViewerComponent` — no new diff logic, per-hunk restore keeps working.
- Pinned to its file by default with a pin/follow toggle. Deliberately avoids the issue #7
  wrong-file resolution class.
- The live file is never written to for display purposes.
- Selection persists by snapshot **id**, not index (indices shift under dedup/filtering).
- Sidebar view is kept and shares components — no breaking change for 1.4.0 workspace layouts.
- `diffComparisonMode` stays a single shared plugin setting across both views.
- New responsive `TimelineBar` (proportional-to-timestamp ticks, clustering, keyboard stepping)
  supersedes `TimelineSliderComponent` in **both** views.

## Open questions / blockers for implementation

- `MarkdownRenderer.render` executes embedded Dataview/`dataviewjs`/Templater blocks present in
  a historical version. Needs a decision before step 2 — plain-source fallback setting, or a blocker.
- Scroll sync is sequenced last, behind a default-off setting. Cut it if it feels janky.
- Split direction under RTL / stacked-tab layouts needs manual verification (`before: true` may
  not land visually left).

An adversarial review of the plan (codex, gpt-5.6-sol, xhigh) was run separately; findings land
in a follow-up commit if they change the plan.

## Adversarial review of the plan (codex gpt-5.6-sol, xhigh)

26 findings, 3 blockers. All load-bearing claims were re-verified against source before
accepting. The plan was rewritten; the significant changes:

- **Phase 0 (extraction) added.** The plan assumed `PastView` could reuse existing pieces, but
  the snapshot session and selection are private to `TimeMachineView`, `ConfirmModal` is
  file-private, and `DiffViewerComponent` renders its own toolbar + comparison toggle +
  full-restore button. Extraction now happens before either view is rewired. This was the
  review's "single most likely reason this plan fails".
- **Two pre-existing bugs found in the shipped sidebar**, to be fixed in the shared code:
    - Stale async results — `updateForFile` awaits slow git work then assigns without rechecking
      that the file is still current (`time-machine-view.ts:89`, `:206`). Needs request generations.
    - Hunk restore can apply the wrong hunk — only `hunkIndex` is carried; on click the diff is
      recomputed against re-read content and the stale ordinal applied (`restore.service.ts:20`).
      Editing during the 1s debounce reorders hunks. Needs a content-revision guard.
- **`next`-mode refresh was wrong.** The plan skipped diff refresh in `next` mode "because the
  live file is irrelevant" — false: the newest snapshot's next target _is_ the live file, and
  current content drives snapshot filtering.
- **"Pinned" renamed to "bound".** `ViewState.pinned` already exists and means Obsidian's own
  leaf pinning — a different concept. Also: actually set `pinned: true` so the leaf is not reused.
- **`View.onResize()` replaces `ResizeObserver`** as the responsive hook (native, testable).
- **Selection state now persists `snapshotTimestamp` alongside `snapshotId`** — the
  nearest-surviving-snapshot fallback needs a timestamp that is unavailable after a restart.
- **`requestSaveLayout()` added** — `setState` alone does not schedule a layout save.
- **Split geometry claim softened** — `createLeafBySplit` documents neither geometry nor sizing;
  `before: true` inserts before the target, visually left in LTR only.
- **Target-leaf algorithm specified** — never split the active leaf blindly; find the root leaf
  showing that exact file. Duplicate detection uses `leaf.getViewState()` because deferred
  leaves expose a `DeferredView`.
- **`TimelineBar` is now a controlled component** (`selectedSnapshotId` in, changes out, no
  auto-select) with a pure layout core, so it is testable without DOM geometry mocks.
- **Command renamed** to "Open past view for current note" — AGENTS.md:254 forbids the plugin
  name in command names.
- **Coalesced snapshot fetching** — a sidebar + past view on one note otherwise runs up to 100
  sequential `git show` subprocesses per poll.
- **Scroll sync removed from the plan** and filed as #13. `scrollIntoView` takes an
  `EditorRange`, not a line; there is no editor-scroll event, no adjacent-editor resolution, and
  rendered blocks carry no source-line metadata. Needs a prototype first.

## BLOCKER — needs a decision before Phase 2

`MarkdownRenderer.render` runs every registered markdown post-processor, so rendering a
historical version executes `dataviewjs` (arbitrary JS) and Dataview queries against the current
index. There is no safe mode, and post-hoc DOM sanitisation is useless because execution already
happened. A historical version may contain a `dataviewjs` block the user has since deleted.

Proposed default, pending approval: neutralise `dataviewjs` / `dataview` / `templater-js` /
`<script>` into inert fenced code blocks before rendering, with `pastViewExecuteBlocks`
(default `false`) to opt back in.
