# 2026-08-27

Past view implemented end to end (issue #9). Plan `documentation/plans/past-view.md` is complete
and has been removed.

## Decision taken

Rendering security: **neutralise before rendering**. `MarkdownRenderer.render` runs every
registered post-processor, so a historical `dataviewjs` would execute against today's vault,
including blocks the user has since deleted. `neutraliseExecutableBlocks` relabels executable
fenced blocks to `text` and escapes inline Dataview before the markdown reaches the renderer.
`pastViewExecuteBlocks` (default off) opts back in.

## Bugs found and fixed along the way

Two in the shipped 1.4.0 sidebar, found while reviewing the plan:

- Stale async results — `updateForFile` awaited a slow git fetch then assigned unconditionally.
- Hunk restore applied a stale ordinal to a recomputed diff.

Three neutralisation bypasses, found by self-audit before review — each meant a historical
`dataviewjs` executed:

- **CRLF notes**: JavaScript's `.` does not match `\r`, so on a CRLF note the fence regex matched
  no lines at all and nothing was neutralised.
- **Blockquotes**: `> ```dataviewjs` did not match a pattern allowing only three leading spaces.
- **List indentation**: a fence indented four or more spaces inside a list item was missed.

From the adversarial review (codex, gpt-5.6-sol, xhigh, 18 findings):

- **BLOCKER, cross-file restore.** `loadFor` set `file` before awaiting but kept the previous
  note's snapshots, so a restore clicked during the fetch combined the new file with the old
  file's snapshot and wrote one note's history into another. Snapshots are now cleared before
  the await, selection resets on a path change (a git id is `git-<hash>` and not file-scoped),
  `selectedSnapshot` refuses a snapshot whose path differs, and both restore paths re-check.
- **Inline Dataview bypass**: `` `$= …` `` runs JavaScript and is not a fenced block. Its
  backticks are now escaped so no code span forms.
- Separate load and diff generations — one counter meant scrubbing cancelled in-flight polls.
- Selection carried its timestamp forward; launcher passes `{id, timestamp}` and applies it to an
  already-open view; duplicate opens serialised through an in-flight map; file-explorer launches
  open the note in a root editor before splitting.
- Follow toggle switches file immediately; `filePath` changes request a layout save; the actions
  menu is hidden with zero snapshots; the ribbon is hidden when the past view is disabled;
  turning off `pastViewExecuteBlocks` re-renders open views; export retries only real collisions
  and reports other failures; debouncers are cancelled on unload; the render generation now
  invalidates on every body transition; timeline keeps keyboard focus across re-render and
  exposes full slider ARIA.
- Deleting a note with a view open made `vault.read` reject with ENOENT (seen live). Reads are
  guarded and degrade to an empty state.

Not adopted: codex's suggestion to replace the language denylist with a container-aware parser.
The denylist plus fence-state tracking is verified against the real Dataview plugin, and a full
CommonMark parser is a large dependency for this surface. Revisit if a further bypass appears.

## Verified in a live vault

Not just unit tests — driven through the Obsidian CLI against the real app: split lands left with
both panes equal width and the leaf pinned; a historical `dataviewjs` does not execute by default
and does execute when opted in; CRLF, blockquote and inline variants all neutralised; state
restores by snapshot id; a deleted file degrades to an empty state; filename collisions get a
numeric suffix; restore refuses a snapshot from another note and leaves that note byte-identical.

## Known gaps

- `past-view.ts` and `past-view-launcher.ts` have no adjacent specs; they are exercised live
  rather than in unit tests. The mock DOM models no tree or layout, so view-level rendering is
  hard to assert on meaningfully.
- Scroll sync between the panes is issue #13, deliberately not implemented.
- RTL and stacked-tab layouts are untested; split placement is observed behaviour, not API
  contract.
